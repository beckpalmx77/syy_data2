Wholesale Data Export API

เอกสารข้อกำหนดทางเทคนิค แนวคิด ขั้นตอนการพัฒนา และคู่มือการเรียกใช้งาน API สำหรับส่งออกข้อมูลการขายส่ง (Wholesale Sales Data) ในรูปแบบ JSON ให้กับระบบภายนอก

Status: Active (Draft Spec) Content-Type: application/json Auth: API Key Header

1. แนวคิดและเป้าหมาย (Concept & Objectives)

ระบบเดิมส่งออกข้อมูลในรูปแบบไฟล์ CSV ผ่านหน้าเว็บ ซึ่งเหมาะสำหรับมนุษย์เปิดดูใน Microsoft Excel แต่ไม่เหมาะกับการเชื่อมต่อแบบอัตโนมัติระหว่างระบบ (System-to-System Integration) เช่น การดึงข้อมูลเข้าสู่ระบบ ERP, CRM, Mobile Application หรือ BI Dashboard


เป้าหมายของการสร้าง RESTful JSON API:

  • Machine-Readable Standard: ให้บริการข้อมูลด้วยรูปแบบ JSON (UTF-8 Encoding) ที่มีโครงสร้างเป็นมาตรฐานสากล
  • Authentication & Security: ปกป้องการเข้าถึงข้อมูลด้วยระบบ API Key ผ่าน HTTP Headers เพื่อยืนยันตัวตนของระบบภายนอก
  • Flexible Query & Filtering: รองรับการค้นหาตามช่วงวันที่ (`doc_date_start` ถึง `doc_date_to`) รหัสพนักงานขาย และการแบ่งหน้า (Pagination)
  • Standard Error Handling: ตอบกลับด้วย HTTP Status Codes (เช่น 200, 400, 401, 500) และข้อความอธิบายความผิดพลาดที่ชัดเจน

2. ขั้นตอนและวิธีการพัฒนา (Implementation Steps)

การพัฒนาไฟล์ API จะดำเนินการภายใต้ชื่อไฟล์ api/v1/export_wholesale.php โดยมีขั้นตอน 4 หลัก ดังนี้:

1
Authentication Layer
ตรวจสอบ Header X-API-KEY หากไม่มีหรือคีย์ไม่ถูกต้อง ให้ส่งตอบกลับ HTTP 401 Unauthorized ทันที
2
Request Validation
รับค่า JSON Body หรือ Query Params (เช่น doc_date_start, doc_date_to) พร้อมตรวจสอบรูปแบบวันที่
3
Database Query
ดึงข้อมูลจาก SQL Server ผ่าน PDO Prepared Statement โดยใช้เงื่อนไขจาก cond_file/doc_info_wholesale.php
4
JSON Formatting
จัดกลุ่มโครงสร้าง JSON ตอบกลับตามมาตรฐาน พร้อมส่ง Header Content-Type: application/json; charset=utf-8

3. การยืนยันตัวตน (Authentication)

ระบบภายนอกที่จะเรียกใช้งาน API ต้องแนบ API Key มาใน HTTP Request Header ทุกครั้ง

Header Key Type คำอธิบาย / ตัวอย่าง
X-API-KEY string รหัสคีย์ประจำระบบภายนอก (เช่น syy_live_secret_key_2026_x89a)
Content-Type string application/json (สำหรับ POST Method)
ข้อควรระวังเรื่องความปลอดภัย:
ห้ามส่ง API Key ผ่าน URL Query String (เช่น ?api_key=xxx) เนื่องจากมีโอกาสหลุดรั่วไปใน Web Server Logs ให้ส่งผ่าน HTTP Header เท่านั้น

4. ข้อกำหนด API Endpoint (Endpoint Specification)

POST /api/v1/export_wholesale.php

Request Parameters (Body / Payload)

Parameter Type Required คำอธิบาย
doc_date_start string จำเป็น วันที่เริ่มต้นในรูปแบบ YYYY-MM-DD หรือ DD-MM-YYYY (เช่น 2026-07-01)
doc_date_to string จำเป็น วันที่สิ้นสุดในรูปแบบ YYYY-MM-DD หรือ DD-MM-YYYY (เช่น 2026-07-30)
slmn_name string | array ไม่บังคับ ชื่อหรือรหัสพนักงานขาย (รองรับมากกว่า 1 คน โดยส่งเป็น Array เช่น ["ก้อย", "ตู่"] หรือข้อความคั่นด้วย , เช่น "ก้อย, ตู่")
iccat_code string | array ไม่บังคับ รหัสหรือชื่อประเภทสินค้า (รองรับมากกว่า 1 ประเภท โดยส่งเป็น Array เช่น ["603", "101-BS01"] หรือข้อความคั่นด้วย , เช่น "603, 101-BS01")
page integer ไม่บังคับ ลำดับหน้าข้อมูลสำหรับ Pagination (Default: 1)
limit integer ไม่บังคับ จำนวนรายการต่อหน้า (Default: 1000, Max: 5000)

JavaScript Fetch API 
async function fetchWholesaleData() {
  const url = 'http://61.7.142.26:8888/syy_data2/api/export_wholesale_api.php';

  const payload = {
    doc_date_start: '30-07-2026',
    doc_date_to: '30-07-2026',
    slmn_name: ['ก้อย', 'น๊อต'],
    iccat_code: ['603', '101-BS01']
  };

  try {
    const response = await fetch(url, {
      method: 'POST',
      headers: {
        'Content-Type': 'application/json'
      },
      body: JSON.stringify(payload)
    });

    const result = await response.json();
    console.log('API Result:', result);
    return result;
  } catch (error) {
    console.error('Error fetching API:', error);
  }
}
Python (requests) 
import requests

url = "http://61.7.142.26:8888/syy_data2/api/export_wholesale_api.php"

    "Content-Type": "application/json"

response = requests.post(url, json=payload, headers=headers)
data = response.json()

if data.get("status") == "success":

    for item in data["data"]:
        print(item["DI_REF"], item["AR_NAME"], item["DEPT_THAIDESC"], item["TRD_B_AMT"])

    print("API Error:", data.get("message"))

7. รหัสตอบกลับความผิดพลาด (HTTP Status Codes & Errors)

HTTP Code Status สาเหตุ / ความหมาย
200 OK success ดึงข้อมูลสำเร็จเรียบร้อย
400 Bad Request error ส่ง Parameter ไม่ถูกต้อง เช่น วันที่ไม่ตรงตามฟอร์แมต YYYY-MM-DD
401 Unauthorized error ไม่ได้แนบ API Key หรือ API Key ไม่ถูกต้อง / หมดอายุ
405 Method Not Allowed error เรียกใช้งานด้วย HTTP Method ที่ไม่รองรับ (เช่น PUT/DELETE)
500 Internal Server Error error เกิดข้อผิดพลาดในการเชื่อมต่อฐานข้อมูล SQL Server
